What changed

The review framework now loads analyze_focus per document type from config/review_frameworks.yaml. For the ETF factsheet type this produces 3 dimensions (risk disclosures completeness, historical performance boundary statements, cost impact on long-term returns), so the plan fans out into 3 concurrent analyze tasks instead of 1 aggregate analyze task. Task count grew from 27 to 29 (25 extract + 3 analyze + 1 synthesize).

What stayed the same

The extract stage is unchanged: 25 chunks, 3 concurrent slots, same fan-out pattern and roughly the same wall-clock time (46.4s baseline fix vs 47.3s here). All 3 analyze dimension tasks still depend on every extract task, and synthesize still depends on all analyze tasks before it can run.

Main trade-off

Total runtime is 79.070s, slightly slower than the 70.022s single-aggregate-analyze rerun, even though analyze itself is now concurrent. The slowest analyze dimension (11.859s) is close to the old single aggregate analyze (9.494s), and synthesize grew from 14.079s to 19.891s because it now consolidates 3 dimension-specific analyses instead of 1. The dimension split trades a bit of throughput for more targeted, per-dimension risk analysis.
