与 v1 / v2 的差异

v1 只到 build_final_result 就结束；v2 只是风险审批的架构草图。当前代码在 review 输出之后插入了 reflect_review_output（反思质量闸门，worklog 14）与 assess_review_risk （风险评估 + 审批路由，worklog 13），两条 review 执行路径（chunk To-Do DAG / single-pass）都先汇合到反思节点，再统一进入风险评估。

审批是路由，不是新执行

route_after_risk_assessment 只根据 state.approval_status 决定走 build_final_result 还是 build_pending_approval_result；两者都直接产出最终 TaskResult， 不会重新触发 extract / analyze / synthesize。人工审批决策的 resume 入口（approval_decision_at / approval_actor_role 字段）已预留在 state 上，但目前还没有对应的恢复节点。

3-1 ToolRegistry 尚未接入

第 3-1 课新增的 ToolRegistry / ToolSpec 查询能力（list_all、 list_by_tag 等）目前只是独立模块，document_review_flow.py 没有导入或调用它。 这套流程仍是确定性 LangGraph pipeline，还不是基于工具调用的 agentic 循环，因此图中不画出对应节点。
