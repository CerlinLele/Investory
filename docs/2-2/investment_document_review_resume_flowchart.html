文字版流程

断点续跑不是记住“上次跑到第几个 task”，而是把上次保存的 results_by_id 和 attempts_by_id 带回同一个 TodoExecutionPlan，重新按依赖层执行。

runner 每次看一个 task：如果它已经有 succeeded 结果，就直接复用；如果还没完成，就先检查依赖是否都成功；依赖不满足则生成 skipped；依赖满足后再检查 retry 预算，预算耗尽则生成 failed，还有预算才调用 executor。

所有分支最后都会回到同一个结果集合，再由 flow 保存新的 resume 状态，并把完成态结果交给最终汇总。

判断顺序

  1. 校验 resume_state.plan 是否等于当前 plan。
  2. 恢复已成功结果和已耗尽失败结果，并复制历史尝试次数。
  3. 对每个 task 先判断是否已有成功结果。
  4. 未完成 task 再判断依赖是否全部 succeeded。
  5. 依赖满足后判断是否还有 retry 预算。
  6. 把复用、跳过、失败、执行结果统一写回结果集合。

核心心智模型

resume 不是“从第 N 步继续跑”，而是把已持久化的 results_by_id 和 attempts_by_id 放回同一个 plan 里，重新按依赖层判断哪些任务已经完成、哪些任务还能跑、哪些下游必须跳过。

哪些任务不会重跑

只有 status=succeeded 的历史结果会被当作已完成任务直接复用。已耗尽 retry 的 failed 会保留下来阻断下游；running、可重试的 failed 和多数 skipped 不会被当成完成态。

为什么要保存 attempts

attempts_by_id 防止恢复后把 retry 次数清零。比如某个任务已经失败 2 次，恢复后应该只剩余真实预算，而不是重新获得一整轮 retry。
