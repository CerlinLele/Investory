# Investory 第 0 章 Session 概念说明

## Session 在 Agent 中的含义

在 agent 系统里，`session` 通常表示一次用户和系统之间的连续交互上下文。

它不是单次任务本身，而是把多次请求串起来的标识。例如：

```text
session_id = abc123
第 1 次请求：总结一篇材料
第 2 次请求：基于刚才总结，生成学习计划
第 3 次请求：继续问里面某个概念
```

如果这三次请求都带着同一个 `session_id`，系统就可以知道它们属于同一次会话。

## 当前第 0 章中的含义

在 Investory 第 0 章里，`session_id` 的含义还很轻：

- 只是 API 协议字段
- 如果请求传了，就原样沿用
- 如果没传，就生成一个新的 UUID
- 暂时不做数据库保存
- 暂时不恢复历史对话
- 暂时不绑定用户身份

所以当前阶段的 `session_id` 更像一个请求链路标识，或者未来会话能力的占位字段。

## 后续可能扩展的能力

后面如果接入 memory 或 session store，`session` 可能会承载：

- 当前用户是谁
- 之前问过什么
- 任务执行历史
- agent 的中间状态
- 上传过的材料
- 工具调用记录
- 多轮问答上下文

## 一句话总结

当前的 `session_id` 只是轻量 tracking ID；未来接入 memory 或持久化存储后，它才会真正变成 agent 的会话上下文入口。
