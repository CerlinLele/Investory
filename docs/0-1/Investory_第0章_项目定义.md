# Investory 第 0 章项目定义

下面这份就是 `Investory 第 0 章项目定义` 的建议版本。第 0 章的目标不是把系统做出来，而是把“要做什么、不做什么、先怎么做”定清楚。

## 项目定位

`Investory` 是一个“投资理财学习助手”，核心目标是帮助用户学习、理解、整理和复盘投资理财相关知识，而不是替用户做投资决策。

它首先是：

- 学习助手
- 知识整理助手
- 风险认知辅助工具
- 结构化学习与复盘工具

它不是：

- 荐股工具
- 择时工具
- 自动交易工具
- 个性化投顾系统
- 收益承诺型产品

## 目标用户

第 0 章先只服务一类用户：有基础数字素养、希望系统学习投资理财的普通学习者。

先不考虑太多复杂用户分层，但默认用户可能有这些需求：

- 看不懂基金、ETF、债券、财报、宏观名词
- 想快速总结文章、报告、课程资料
- 想做学习计划和阶段复盘
- 想形成自己的知识卡片和风险认知

## 核心价值

`Investory` 第一性价值不是“给答案”，而是“帮助用户形成判断能力”。

所以它提供的价值应当是：

- 降低学习门槛
- 提高信息整理效率
- 强化结构化理解
- 帮助用户记录学习过程
- 帮助用户识别风险和不确定性

## 第 0 章范围

第 0 章只做“定义系统蓝图和最小工程边界”，不追求完整功能，不急着接真实数据源。

第 0 章要明确的能力范围：

- 支持最小任务类型定义
- 支持系统三层结构定义
- 支持后续模块拆分规划
- 支持安全边界和风险边界定义

第 0 章不要求：

- 完整前端
- 完整 RAG
- 真实基金/行情 API 接入
- 多代理协作
- 自动化工作流
- 长期记忆体系
- 完整评测平台

## 第一版任务类型

建议第 0 章先定义 3 类任务，后面所有模块都围绕这 3 类扩展：

1. `qa`
   - 理财概念问答
   - 例如：什么是 ETF、久期是什么意思、基金回撤怎么看

2. `summary`
   - 文章、财报、课程材料摘要
   - 例如：帮我总结这篇基金分析文章的重点

3. `study_plan`
   - 学习计划与复盘建议
   - 例如：给我做一个 2 周的 ETF 入门学习计划

这 3 类任务足够支撑后续：

- 单次请求
- 结构化输出
- 工具接入
- 会话状态
- 安全策略
- Eval

## 系统边界

第 0 章必须先把系统边界收住。

系统内要做的：

- 接收用户任务
- 分类任务类型
- 组装上下文
- 生成回答或学习结构化结果
- 输出风险提示
- 记录最小任务日志和会话信息

系统外先不做的：

- 实时交易
- 自动下单
- 资产托管
- 个性化收益预测
- 明确买卖建议
- 高风险策略生成

## 安全与合规边界

这部分对 `Investory` 非常关键，应该在第 0 章就定下来。

默认规则：

- 输出仅用于学习与研究，不构成投资建议
- 对直接荐股、择时、仓位建议进行拒答或收束
- 对基金、行情、新闻类内容标注数据时间
- 对高不确定性内容明确说明信息局限
- 对用户“帮我决定买什么”这类请求，引导回学习分析框架，而不是直接给结论

## 系统三层定义

控制面：

- 请求入口
- 任务分类
- session / route
- 安全策略
- 后续 planner 接入点

执行面：

- 模型调用
- 摘要生成
- 问答生成
- 后续工具调用
- 后续 skills 执行

状态层：

- session transcript
- 任务日志
- 后续学习偏好
- 后续风险偏好
- 后续 checkpoint / eval / trace

## 第 0 章完成标准

第 0 章完成，不是指“功能多”，而是指下面这些定义已经稳定：

- 项目定位清楚
- 用户范围清楚
- 第一版任务类型清楚
- 系统边界清楚
- 风险边界清楚
- 三层结构清楚
- 后续章节知道往哪里扩

## 一句话定义

`Investory` 是一个以学习、理解、整理和复盘为核心的投资理财学习助手，按 `控制面 + 执行面 + 状态层` 设计，第一版聚焦 `qa / summary / study_plan` 三类任务，并明确拒绝直接投资决策型输出。
