# Investory 第 0 章项目定义

第 0 章的目标不是把系统做出来，而是把 `Investory` 的项目定位、能力边界、第一版 MVP 和后续工程方向定清楚。

## 项目定位

`Investory` 是一个投资理财学习助手，核心目标是帮助用户学习、理解、整理和复盘投资理财相关知识，而不是替用户做投资决策。

它首先是：

- 学习助手
- 知识整理助手
- 风险认知辅助工具
- 结构化学习与复盘工具

它不是：

- 荐股工具
- 择时工具
- 自动交易工具
- 个性化投顾系统
- 收益承诺型产品

核心原则：

**先做“帮助用户学会判断”，不要做“替用户下判断”。**

## 目标用户

第 0 章先只服务一类用户：有基础数字素养、希望系统学习投资理财的普通学习者。

先不考虑复杂用户分层，但默认用户可能有这些需求：

- 看不懂基金、ETF、债券、财报、宏观名词
- 想快速总结文章、报告、课程资料
- 想做学习计划和阶段复盘
- 想形成自己的知识卡片和风险认知

## 核心价值

`Investory` 第一性价值不是“给答案”，而是“帮助用户形成判断能力”。

它提供的核心价值包括：

- 降低学习门槛
- 提高信息整理效率
- 强化结构化理解
- 帮助用户记录学习过程
- 帮助用户识别风险和不确定性

## 为什么适合作为课程项目

这个项目和课程大纲的主线高度匹配：

- `单次请求`：解释一个理财概念，或总结一篇研报、财报、财经文章
- `规划/结构化输出`：判断用户是在问概念、做对比、整理资料，还是生成学习计划
- `工具/MCP`：后续可接行情、财经日历、基金资料、新闻源
- `FastAPI/Gateway`：可以做成可调用的后端服务
- `Runtime/Skills`：沉淀基金分析、财报阅读、资产配置等 Skill
- `状态管理`：记录学习进度、风险偏好、已读内容、复盘记录
- `Eval`：校验回答是否事实错误、是否越界成投资建议
- `安全基线`：强制风险提示、拒绝直接荐股、标注数据时间

## 项目边界

系统内要做的：

- 投资理财知识问答：基金、债券、ETF、资产配置、风险收益、估值、复利、仓位管理
- 新闻、研报、财报学习整理：提炼重点、解释术语、生成学习笔记
- 基金或 ETF 基础信息整理：结构化展示基础信息、费用、风险点和学习要点
- 风险认知训练：用问卷和案例帮助用户理解风险偏好
- 模拟练习：虚拟组合、回测入门、情景分析、复盘记录
- 学习路径规划：按新手、进阶、专题生成学习计划和练习

系统外先不做的：

- 直接给出“买哪个、什么时候买、买多少”
- 个性化投资建议
- 实时交易
- 自动下单
- 资产托管
- 个性化收益预测
- 高风险策略推荐
- 用不透明 prompt 直接输出投资结论

## 第 0 章范围

第 0 章只做“定义系统蓝图和最小工程边界”，不追求完整功能，不急着接真实数据源。

第 0 章要明确：

- 支持最小任务类型定义
- 支持系统三层结构定义
- 支持后续模块拆分规划
- 支持安全边界和风险边界定义

第 0 章不要求：

- 完整前端
- 完整 RAG
- 真实基金/行情 API 接入
- 多代理协作
- 自动化工作流
- 长期记忆体系
- 完整评测平台

## 第一版 MVP

第一版建议只做 4 个能力：

1. 理财概念问答
2. 财经文章或财报摘要
3. 基金或 ETF 基础信息整理
4. 学习计划与复盘记录

对应的最小任务类型：

1. `qa`
   - 理财概念问答
   - 例如：什么是 ETF、久期是什么意思、基金回撤怎么看

2. `summary`
   - 文章、财报、课程材料摘要
   - 例如：帮我总结这篇基金分析文章的重点

3. `instrument_brief`
   - 基金或 ETF 基础信息整理
   - 例如：帮我整理这只 ETF 的基础信息、费用结构和主要风险点

4. `study_plan`
   - 学习计划与复盘建议
   - 例如：给我做一个 2 周的 ETF 入门学习计划

这 4 类任务足够支撑后续：

- 单次请求
- 结构化输出
- 工具接入
- 会话状态
- 安全策略
- Eval

## 系统三层定义

控制面：

- 请求入口
- 任务分类
- session / route
- 安全策略
- 后续 planner 接入点

执行面：

- 模型调用
- 摘要生成
- 问答生成
- 后续工具调用
- 后续 skills 执行

状态层：

- session transcript
- 任务日志
- 后续学习偏好
- 后续风险偏好
- 后续 checkpoint / eval / trace

## 安全与合规边界

这部分对 `Investory` 非常关键，应该在第 0 章就定下来。

默认规则：

- 输出仅用于学习与研究，不构成投资建议
- 对直接荐股、择时、仓位建议进行拒答或收束
- 对基金、行情、新闻类内容标注数据时间
- 对高不确定性内容明确说明信息局限
- 对用户“帮我决定买什么”这类请求，引导回学习分析框架，而不是直接给结论

## 后续迭代方向

等第一版稳定后，再逐步增加：

1. 行情与新闻工具接入
2. 模拟组合
3. 风险测评
4. 结构化分析模板
5. 学习进度与复盘历史
6. 面向安全边界的自动评测

## 第 0 章完成标准

第 0 章完成，不是指“功能多”，而是指下面这些定义已经稳定：

- 项目定位清楚
- 用户范围清楚
- 第一版任务类型清楚
- 系统边界清楚
- 风险边界清楚
- 三层结构清楚
- 后续章节知道往哪里扩

## 一句话定义

`Investory` 是一个以学习、理解、整理和复盘为核心的投资理财学习助手，按 `控制面 + 执行面 + 状态层` 设计，第一版聚焦 `qa / summary / instrument_brief / study_plan` 四类任务，并明确拒绝直接投资决策型输出。
