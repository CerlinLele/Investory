Minimal Orchestration Flow

Investory 最小编排适用场景流程图

入口编排层只做一次分流判断：缺字段、投资建议请求、可执行学习任务是三个并行分支。 只有学习任务分支会继续映射到 qa / summary / brief，并复用现有 TaskExecutor。

入口分流：三个并行分支

LearningEntryFlow.run(input) -> TaskResult

接收用户请求

输入是原始 payload，用户不需要提前知道内部 task_type。

入口判断与分流

同一层判断请求应该进入哪条分支；三条分支是互斥的并行结果。

分支 A：缺字段

返回补充信息提示

例如只有 question、缺 material_text；或只有 instrument_name_or_code、缺 source_material。

TaskResult: ask_for_missing_input
分支 B：可执行学习任务

映射到已注册任务

字段足够且不属于直接投资建议时，才进入现有任务执行链路。

任务类型判断

映射到最小任务集合。

qa -> finance_qa summary -> learning_material_summary brief -> instrument_brief

调用现有 TaskExecutor

编排层不重做执行逻辑。

TaskSpec
TaskExecutor
prompt_loader
RequestRunner
TaskResult
TaskResult: learning task response
分支 C：投资建议请求

拒答并给学习替代方向

不提供买卖、择时、个性化配置建议；统一改写为安全边界内的学习型响应。

TaskResult: refuse_and_redirect

关键点：三条分支不是顺序执行的 step 1 / step 2 / step 3。 它们是入口分类后的三个并行出口；只是学习任务分支内部还有后续执行步骤。

实现边界

这条 flow 只包含判断和分流。TaskExecutor 之后的 prompt 加载、模型调用、结构化输出， 仍属于现有最小任务执行链路，不拆成新的编排节点。
