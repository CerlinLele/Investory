Investory instrument_profile HTTP 工具调用流程分析

生成时间：2026-05-15（Australia/Sydney）

1. 结论概览

当前项目的 HTTP 工具调用不是“模型直接联网”，而是通过动作编排链路触发：当 instrument_brief 仅缺 source_material 时，系统自动选择 fetch_then_run_instrument_brief，再由执行器调用 fetch_instrument_profile，最终通过 net_guard.guarded_get 发起受控 HTTP 请求。

2. 端到端调用主链路

  1. DecisionFlow 入口：DecisionFlow.run 依次执行 planner/validator/router/executor（src/investory/agent_core/runtime/decision_flow.py:56-64）。
  2. Planner 决策：若任务是 instrument_brief 且缺失字段仅为 source_material，则返回动作 fetch_then_run_instrument_brief（src/investory/agent_core/runtime/decision_planner.py:13-26）。
  3. Validator 校验：要求 instrument_name_or_code 非空且 payload 为 dict（src/investory/agent_core/actions/validator.py:80-90）。
  4. Router 路由：动作映射到 FetchThenRunInstrumentBriefExecutor（src/investory/agent_core/actions/router.py:41-43）。
  5. Executor 执行：调用 fetch_instrument_profile 获取资料；失败则返回 requires_user_input；成功则回填 source_material/source_links/source_as_of 后运行任务模型（src/investory/agent_core/actions/executors.py:76-104）。
  6. Tool 实际抓取：fetch_instrument_profile 执行多来源顺序尝试并调用 guarded_get（src/investory/agent_core/tools/instrument_profile.py:112-170）。
  7. Net Guard 控制：validate_url 强制 https + allowlist host，guarded_get 统一 timeout、content-type、HTTP/network 异常归一化（src/investory/agent_core/tools/net_guard.py:49-132）。

4. 错误与降级策略

  • 错误类型域：invalid_input/blocked_host/timeout/network_error/parse_error/not_found（instrument_profile.py:15-22）。
  • 重试语义由 ERROR_RETRYABLE_POLICY 固定，不直接信任上游值（instrument_profile.py:31-38,77-87）。
  • Executor 侧不把工具错误直接抛给用户，而是统一降级为“请用户粘贴资料”路径（actions/executors.py:80-97）。

5. 当前实现特征与注意点

  • 已具备“先治理后请求”的结构：工具层不裸连网，网络规则集中在 net_guard。
  • 当前候选源仍是示例域名（example.com），生产可用性依赖后续替换为真实数据源与 allowlist 配置。
  • 成功结果已经回填 source_links 与 source_as_of，可解释性链路完整。

6. 主链路速记（用于评审）
