# Investory：第 3-1 课「工具发现、调用与 MCP 协同」落地计划

## 1. 目标与产出

目标：在 Investory 中复现并讲清楚“Agent 如何决定联网、如何调用 HTTP/Web 工具、如何做安全治理”的完整链路。

本阶段产出：
1. 一份代码定位文档：`Investory HTTP 工具调用逻辑代码定位.md`
2. 一份课程版最小主链路（5 个关键文件/函数）
3. 一份补充说明：为什么 Agent 看起来会“自己判断请求哪个网址”

## 2. 范围定义（先定边界）

1. 工具范围
- `web_search`（搜索类）
- `web_fetch/http`（抓取或通用 HTTP 类）
- `gateway/mcp`（若存在远程工具转发）

2. 运行时范围
- 工具注册与注入
- 工具路由与执行
- provider 选择与 fallback
- 网络治理（SSRF/allowlist/timeout/proxy/retry）

3. 不纳入首轮
- 业务层 prompt 调优细节
- UI 层展示逻辑
- 与第 3-1 课无关的任务编排模块

## 3. 实施阶段

### 阶段 A：代码普查与命名对齐

目标：找全 Investory 里与 Web/HTTP/MCP 相关的实现入口。

执行项：
1. 全局检索关键词：`web_search`, `web_fetch`, `http`, `fetch`, `tool`, `registry`, `router`, `mcp`, `gateway`, `ssrf`, `timeout`, `proxy`。
2. 画出“入口文件清单”：工具导出层、工具装配层、runtime 层、网络安全层。
3. 统一术语映射：把 Investory 内部命名映射到课程术语（Tool Contract / Tool Registry / Handler / Runtime Guard）。

验收标准：
- 有一张“模块 -> 文件路径 -> 职责”表。
- 能明确说出 web 工具是否为本地执行、托管执行或混合执行。

### 阶段 B：调用链路定位（Search / Fetch / Gateway）

目标：把“从模型到网络请求”的路径走通并可复述。

执行项：
1. `web_search`：定位 schema、tool 入口、runtime、provider 选择、fallback。
2. `web_fetch/http`：定位 schema、tool 入口、真实请求函数、结果标准化。
3. `gateway/mcp`：定位参数校验、权限注入、远程调用适配和错误归一化。

验收标准：
- 每条链路给出“起点函数 -> 关键中间函数 -> 终点函数”。
- 每条链路至少 3 个代码锚点（文件:行号）。

### 阶段 C：治理链路定位（安全与稳定性）

目标：确认 Investory 如何避免“能连网但不受控”。

执行项：
1. SSRF：私网 IP、主机名策略、重定向策略、DNS 解析策略。
2. 超时与重试：request timeout、attempt timeout、retry/backoff。
3. 代理与凭据：proxy 注入、凭据读取边界、最小权限作用域。
4. 审计与可观测：请求日志、provider 标识、错误分类。

验收标准：
- 有“安全控制点清单”（控制点 -> 代码位置 -> 触发条件 -> 失败行为）。

### 阶段 D：形成课件化文档

目标：产出可直接用于第 3-1 课讲解的文档结构。

执行项：
1. 复用你当前 OpenClaw 文档结构，按 Investory 路径替换。
2. 增加“为什么 Agent 会自己判断网址”的补充节。
3. 增加“最小主链路（5 点）”用于授课时快速走读。

验收标准：
- 文档 6~8 个小节，结构完整且可独立阅读。
- 每个结论都有代码锚点，不写纯口头判断。

## 4. 推荐文档骨架（Investory 版本）

1. HTTP 工具注册入口
2. `web_fetch/http` 调用链路（本地工具 -> 网络请求 -> 结构化结果）
3. `web_search` 调用链路（provider 选择与回退）
4. `gateway/mcp` 调用链路（远程工具适配）
5. 网络安全治理（SSRF、超时、代理、权限）
6. 与第 3-1 课知识点映射
7. 建议课件最小主链路
8. 补充：为什么 Agent 会“自己判断网址”

## 4.1 详细 Implementation Steps（可逐步 Review）

说明：以下每一步都控制在 15~45 分钟内，完成后即可单独 review。

### A. 代码普查与命名对齐

1. 建立检索记录文件
- 输入：当前仓库。
- 操作：新建 `docs/3-1/worklog/http-tooling-scan.md`，写入本轮检索时间、分支名、检索人。
- 输出：可追溯的扫描日志文件。
- Review 点：文件存在，基础元信息完整。

2. 执行第一轮关键词检索（工具类）
- 输入：关键词 `web_search|web_fetch|tool|registry|router`。
- 操作：全仓检索并把命中路径写入日志，先不做结论。
- 输出：原始命中清单（路径级）。
- Review 点：命中清单覆盖 `src/` 与 `docs/`，无主观筛选。

3. 执行第二轮关键词检索（网络治理类）
- 输入：关键词 `http|ssrf|timeout|proxy|retry|allowlist`。
- 操作：同样记录命中路径，并标记“高相关/待确认”。
- 输出：网络治理候选文件清单。
- Review 点：每个候选文件至少有 1 个命中词证据。

4. 合并并去重候选文件
- 输入：步骤 2 与步骤 3 的路径结果。
- 操作：按模块分组去重，形成 `候选文件 v1`。
- 输出：分组后的候选文件表（tool/export/runtime/security）。
- Review 点：每个文件只出现一次且分组理由明确。

5. 建立术语映射表 v1
- 输入：候选文件 v1。
- 操作：建立“Investory 内部命名 -> 课程术语”映射（Contract/Registry/Handler/Guard）。
- 输出：术语映射表 v1。
- Review 点：每条映射至少绑定 1 个代码文件。

6. 产出阶段 A 小结
- 输入：步骤 1~5 的结果。
- 操作：写 5~10 行阶段结论，仅描述“看到了什么”，不做推测。
- 输出：阶段 A 小结块。
- Review 点：结论均可回溯到日志路径。

### B. 调用链路定位（Search / Fetch / Gateway）

7. 定位 `web_search` schema 定义
- 输入：候选文件 v1。
- 操作：定位参数结构、默认值、必填字段、返回结构。
- 输出：`web_search` schema 锚点列表（文件:行号）。
- Review 点：至少包含定义点与消费点各 1 个。

8. 定位 `web_search` 执行入口
- 输入：步骤 7 结果。
- 操作：确认从工具注册到 handler 的第一跳函数。
- 输出：`web_search` 起点函数与调用方。
- Review 点：能画出“注册 -> 调用”一跳关系。

9. 定位 `web_search` provider 选择与 fallback
- 输入：`web_search` 执行路径。
- 操作：找出 provider 决策条件、回退触发条件、失败处理。
- 输出：provider/fallback 条件表。
- Review 点：每个条件有代码证据，不靠口述。

10. 定位 `web_fetch/http` schema 与入口
- 输入：候选文件 v1。
- 操作：重复步骤 7~8 方法于 `web_fetch/http`。
- 输出：`web_fetch/http` schema+入口锚点。
- Review 点：包含请求参数与返回规范位置。

11. 定位真实 HTTP 请求触发点
- 输入：步骤 10 结果。
- 操作：追踪到真正发起请求的方法（client/session/request）。
- 输出：`web_fetch/http` 终点函数锚点。
- Review 点：可确认“这里就是实际联网点”。

12. 定位结果标准化逻辑
- 输入：步骤 11 结果。
- 操作：找输出清洗/结构化/错误包装位置。
- 输出：结果标准化函数列表。
- Review 点：至少 1 处成功路径和 1 处错误路径。

13. 定位 `gateway/mcp` 参数校验与适配
- 输入：候选文件 v1 中 mcp/gateway 相关文件。
- 操作：定位请求入参校验、权限注入、协议转换。
- 输出：`gateway/mcp` 中间层锚点列表。
- Review 点：覆盖校验、适配、执行三类节点。

14. 定位 `gateway/mcp` 错误归一化
- 输入：步骤 13 结果。
- 操作：定位异常映射、错误码转换、可观测字段注入。
- 输出：错误归一化映射表。
- Review 点：至少列出 2 类不同错误映射。

15. 产出三条链路草图 v1
- 输入：步骤 7~14 结果。
- 操作：各写“起点 -> 中间 -> 终点”三段式，不超过 8 行/链路。
- 输出：Search/Fetch/Gateway 三条链路草图。
- Review 点：每条链路至少 3 个锚点。

### C. 治理链路定位（安全与稳定性）

16. 定位 SSRF 前置检查
- 输入：security 候选文件。
- 操作：查 host/ip 校验、私网拦截、域名规则。
- 输出：SSRF 检查点列表。
- Review 点：列出触发条件与拦截行为。

17. 定位重定向与 DNS 策略
- 输入：HTTP 客户端配置代码。
- 操作：确认是否允许重定向、最大跳数、DNS 解析策略。
- 输出：redirect/DNS 策略记录。
- Review 点：配置值或默认值可定位。

18. 定位 timeout/retry/backoff
- 输入：request 执行链路。
- 操作：分层记录超时（全局/单次）与重试策略。
- 输出：timeout/retry 参数表。
- Review 点：参数值与生效位置一一对应。

19. 定位 proxy/credential 边界
- 输入：配置加载与网络调用文件。
- 操作：确认代理注入来源、凭据读取路径与作用范围。
- 输出：proxy/credential 边界说明。
- Review 点：能区分“可配置入口”和“实际使用点”。

20. 定位日志与错误分类
- 输入：链路中的 logging/error 代码。
- 操作：记录 request id、provider、error class 等字段。
- 输出：可观测字段清单。
- Review 点：至少一条成功日志和一条错误日志路径。

21. 产出安全控制点清单 v1
- 输入：步骤 16~20。
- 操作：整理“控制点 -> 位置 -> 触发 -> 失败行为”四列表。
- 输出：安全控制点清单 v1。
- Review 点：每行都有代码锚点。

## 6. 风险与应对

1. 风险：Investory 命名与 OpenClaw 差异大，难以一一对应。
- 应对：先做术语映射表，再写正文，避免硬套。

2. 风险：部分联网能力在平台托管侧，代码里看不到“真实请求”。
- 应对：文档中明确区分“本地执行”与“托管执行”。

3. 风险：安全逻辑分散在 infra 多处，容易漏点。
- 应对：按“请求前/请求中/请求后”三段做 checklist 逐项核对。
