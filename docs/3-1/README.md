## 📊 内容速览

### 执行总览与快速参考
**用时**: 5 分钟 | **内容**: 全局地图、四阶段对照表、快速参考、常见问题

**推荐所有人都读** — 这是入口文档,理解全局后再深入细节。

**要点**:
- 四个 Phase 共 2 天,只做**工具管理**
- Phase 1 必做,其它可选但推荐
- 不做 Mock 执行器、Plan Handler(那是测试/流程的事)
- 三种执行路线供选择

---

### 业务贴合落地计划
**用时**: 15 分钟 | **内容**: 项目现状分析、为什么只做工具管理、架构决策

**推荐实施前读** — 理解"为什么是这样"而不是"怎么做"。

**关键发现**:
- 项目是 **LangGraph 确定性管线**,不是 ReAct agent
- ToolRegistry/LoopEngine 是死代码,保留作为第 3-2 课的预埋
- 真正适配的是: **能力台账 + 工具发现 + 访问控制 + 审计日志**
- 不做 Mock 执行器(测试基础设施,不属于工具管理)
- 不做 Plan Handler 抽象(规划策略,不属于工具管理)

---

### 通用借鉴方案
**用时**: 20 分钟 | **内容**: 课程四个模块的详细说明

**参考性文档** — 了解课程设计思路,但项目只采用其中的工具管理部分。

---

### Phase 1 - 4 实施指南
**用时**: 各 0.5 小时(含编码) | **内容**: 每个 Phase 的代码改动、测试写法、提交信息

**行动文档** — 决定开始做时,打开对应 Phase 的实施指南,跟着清单逐步完成。

**每个 Phase 包含**:
- 完整的代码片段(可复制粘贴)
- 改动清单(确保没遗漏)
- 验证步骤(pytest 命令)
- Commit message 模板

**四个 Phase 的关键区别**:
- **Phase 1**:元数据定义(TaskSpec 扩展)
- **Phase 2**:发现接口(routing 查询函数)
- **Phase 3**:访问控制(基于角色的验证)
- **Phase 4**:审计日志(执行追踪+LoopEngine 说明)

## 🚀 建议的开始方式

## 📞 问题排查

### Q: Phase 1 改完后,其它测试失败了
**A**: 检查是否给现有 TaskSpec 补了默认值。应该用 `= "read"` 和 `= ""`。

### Q: 能只做 Phase 1 和 2,跳过 3 和 4 吗?
**A**: 可以。Phase 1+2 已经解决"工具可查"的问题。Phase 3+4 是为未来做准备。

### Q: 改完后还要改 FastAPI 接口吗?
**A**: 不需要。这些改动都在内部架构层。外部 API 保持不变。
