## 📊 内容速览

### 执行总览与快速参考
**用时**: 5 分钟 | **内容**: 全局地图、四阶段对照表、快速参考、常见问题

**推荐所有人都读** — 这是入口文档,理解全局后再深入细节。

**要点**:
- 四个 Phase 共 3.5 天,累进式收益
- Phase 1 必做,其它可选
- 不要做课程模块二(你的架构不需要)
- 三种执行路线供选择

---

### 业务贴合落地计划
**用时**: 15 分钟 | **内容**: 项目现状分析、三个真正适配的借鉴点、为什么不做模块二

**推荐实施前读** — 理解"为什么是这样"而不是"怎么做"。

**关键发现**:
- 项目是 **LangGraph 确定性管线**,不是 ReAct agent
- ToolRegistry/LoopEngine 是死代码,但保留作为预埋
- 真正适配的是: **能力台账** + **Mock 执行器** + **Plan Handler 可替换** + **治理框架**
- 动态注入(模块二)不适配,原因:模型已经不自由选工具

---

### 通用借鉴方案
**用时**: 20 分钟 | **内容**: 课程四个模块的详细说明和代码示例

**参考性文档** — 如果你对课程内容有疑问,这里是参考。但**不是行动指南**。

---

### Phase 1 - 4 实施指南
**用时**: 各 1~1.5 小时(含编码) | **内容**: 每个 Phase 的代码改动、测试写法、提交信息

**行动文档** — 决定开始做时,打开对应 Phase 的实施指南,跟着清单逐步完成。

**每个 Phase 包含**:
- 完整的代码片段(可复制粘贴)
- 改动清单(确保没遗漏)
- 验证步骤(pytest 命令)
- Commit message 模板

**为什么分离**:
- 每个 Phase 可独立完成和提交
- 如果中途改变计划,不影响后续
- 易于代码审查(小的、有主题的 PR)

---

### LoopEngine何时启用
**用时**: 10 分钟 | **内容**: LoopEngine 保留的原因、启用时机、迁移清单

**参考性+规划文档** — 现在不用做,但 3-6 个月后可能需要。预先知道"什么时候启用"有助于架构决策。

**关键**:
- 保留 LoopEngine 是为 MCP 工具集成(第 3-2 课)做预埋
- 启用时机有三个触发条件
- 3-phase 渐进式启用计划

## 📞 问题排查

### 问题:Phase 1 改完后,其它测试失败了
**检查**:
1. 是否给现有 TaskSpec 补了默认值?应该用 `= "read"` 和 `= ""`
2. 是否有导入错误?看是否改了 `__init__.py`

### 问题:Phase 2 flow 测试仍然很慢
**检查**:
1. 是否真的用了 MockTaskExecutor?检查 fixture 的 executor 参数
2. Mock 是否包含了所有被调用的任务?打印 `executor.get_call_count()` 看

### 问题:Phase 3 现有 flow 测试失败
**检查**:
1. DefaultAdaptivePlanHandler 是否正确实现?应该代理给 ChunkRulePlanHandler 或 LLMPlanHandler
2. flow 的 `_default_plan_handler()` 是否返回了 DefaultAdaptivePlanHandler 实例?

### 问题:Phase 4 权限测试失败
**检查**:
1. `side_effect_level` 是否正确赋值?只有 risk_assessment 是 `"write"`,其余是 `"read"`
2. `validate_task_access()` 逻辑是否正确?admin 全允许,analyst 只允许 read 级任务
